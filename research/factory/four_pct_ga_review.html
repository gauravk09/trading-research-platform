You still can't trade it.

Two genetic searches, one portfolio judge, and three separate bars — the machine's own holdout, a shuffled-label placebo floor, and the post-audit bookrunner. The trigger passed one, tied one, and lost the last. This is the closing review for the four_pct long.

Verdict — factor-only, budget spent

In plain terms: a 4%-up-day on its own loses money. The search engine did find genuine skill at picking which 4% days are less bad — worth about +0.19R per trade against a matched random control, which is a real effect, not noise. But when that pick is run as an actual book — real position limits, real costs — it still loses −11.9% CAGR, and it loses worse than the random control at −9.8%.

The reason is mechanical, not statistical. A 4%-day cohort means tight stops and high frequency. Cost in R terms is 2 × cost ÷ stop_pct, so tight stops multiply the cost, and the 10-slot book saturates (56% of signals skipped). The pocket's tighter stops shrink the rupee win while paying the same rupee cost — so it trails a control that takes wider, lazier trades.

Selection skill is real. Tradeable edge is not. The long side of four_pct is closed; the edge on this trigger lives on the short sibling.

ACT 2

The fitted-pocket search ties the noise floor

2026-08-11 · genome: pocket --fit

New mode, adopted from the FunSearch principle: the GA proposes only structure ([series, op], no thresholds); the framework grid-fits the numbers per CV fold on train-only quantiles and scores on the held-out fold. More search flexibility means a higher null bar — so the placebo floor was re-measured for this mode before the real run.

Note what the engine converged on: ret21 ≤ −4.5, rs ≤ 18.8 — low 21-day return, bottom-decile relative strength. It is selecting oversold laggards. These pockets are less bad than the naked trigger (hence beating 88–100% of null subsets) but still absolutely negative. Less-bad-than-a-loss is not an edge.

The floor here is flattered, not earned. Two of the three shuffled searches could not score above 0.00 — because naked four_pct era-A expectancy is already negative. The placebo floor is partially shielded by the trigger's own bleed, so 0.51 likely understates the true null bar. Record it; don't celebrate it. Even against this soft floor, the real run only managed a tie.

CAVEATS

What would change this reading

  • The placebo floor is soft. 0.51 was set with two of three shuffles stuck at 0.00 because the naked trigger bleeds. A trigger with positive baseline expectancy would produce a higher, more honest floor — so the Act-2 tie is, if anything, generous to the real run.
  • The Act-1 log predates the committed engine. four_pct_s1_seeded.json (Aug 06) diverges from a HEAD replay after generation 1. HEAD-replay is the valid reference; the stored log is a record, not a reproducible artifact.
  • Mild full-sample look-ahead in Act 3. The condition bucket is qcut over the full cohort exactly as certified. A live rule would need a fixed threshold — irrelevant here because the verdict is negative anyway, but it would matter if the sign flipped.
  • Three seeds never evaluated. d1_deliv_veto, d2_deliv_regime, c3_R5_system all reference deliv_x20 and were unevaluable. The delivery family is untested on this trigger.
  • Only the long side is closed. Everything here is side: long. The four_pct-down / short sibling is where the edge was previously found, and none of this touches it.
